# Рефакторинг пакетной структуры

Цель: Python-пакет вместо скриптов в корне, явные границы подсистем, единый CLI,
E2EE как основной путь, frontend по функциям, актуальные инструкции и проверенный
экспериментальный релиз. Перенос файлов не является завершением работы.

## Критерии готовности

- `src/codex_workspace`: agent, codex, crypto, devices, relay, domain, cli, ops.
  Domain содержит только общие модели/правила; ops Python обслуживает команды,
  корневой ops — ресурсы установки. Тесты находятся в tests.
- Установка пакета и команды работают вне checkout. Состояние задаётся через
  CODEX_WORKSPACE_STATE, source checkout нужен только для релиза и задаётся
  CODEX_WORKSPACE_SOURCE. Рабочие данные не перемещаются вслед за исходниками.
- Чистая сборка релиза, проверка артефакта, CI, корректные systemd/launchd команды.
- Подтверждённо неиспользуемый открытый транспорт удалён; миграции и локальные
  журналы исполнения сохранены. E2EE, авторизация и права задач не ослаблены.
- Frontend разделён по функциям; статусы и протоколы имеют общие определения.
- main остаётся однопользовательским; experimental сохраняет права участников.
- Проверены каталог, история, отправка/ответ, вложения, квота, диагностика,
  привязка и push. Отдельно указаны неподтверждённые проверки настоящего iPhone.
- Обе ветки закоммичены и отправлены, experimental развёрнут, службы используют
  прежние ключи/очереди, приватные временные файлы убраны.

## Порядок

1. Перенос без изменения протокола, установка и тесты вне checkout.
2. Разделение зависимостей и удаление дублирующих транспортов.
3. Frontend и документация.
4. Rebase experimental, проверка прав/регрессий, чистая сборка релиза.
5. Согласованный deploy, безопасное обновление локальных служб, проверка и cleanup.

## Реализовано

Python-пакет, тесты, frontend и ресурсы установки перенесены. Проверены wheel
вне checkout, единый CLI, E2EE checkpoint и запрет открытых исходящих маршрутов.
Устаревший ручной контроллер и открытые HTTP-обработчики содержимого удалены;
модели хранения, миграции и данные сохранены. В корне четыре отслеживаемых
файла: AGENTS.md, README.md, pyproject.toml и .gitignore.

Frontend использует только E2EE-клиент, включая историю, вложения, диагностику
и push. Подмены для тестов интерфейса находятся в tests/fixtures и подключаются
только Playwright. Криптографические тесты используют настоящий клиент и
проверяют обмен Python ↔ browser, подписи, контекст, восстановление ключей,
вложения и отказ открытого транспорта даже до привязки устройства.

Установщик создаёт отдельное окружение каждого релиза и переключает службу
после проверок; повторная установка активного релиза ничего не меняет.
Локальные службы запускают установленный пакет с явным каталогом состояния,
поэтому rebase исходников не прерывает их работу. Ключи и очереди сохранены.

Экспериментальное расширение сохраняет свою схему БД и проверку доступа.
Общие изменения входят через rebase main; в Yandex Cloud устанавливается только
experimental/multi-user. Ревизия и хеш артефакта записываются установщиком.

## Проверки и ограничения

На этапе завершения пройдены 398 Python-тестов основной ветки и 406
экспериментальной; браузерные сценарии — 43 и 48 соответственно. Обе сборки
включают service worker. Изменения не требуют сброса ключей или миграции данных.

GitHub Actions не запускает jobs из-за ограничения оплаты аккаунта; локальные
результаты не означают успешный запуск CI. Настоящий iPhone после рефакторинга
не проверялся: автоматизированные мобильные сценарии не заменяют эту проверку.
Операционная проверка релиза подтверждает версию и здоровье служб, а не новый
пользовательский запрос через доверенное устройство.
